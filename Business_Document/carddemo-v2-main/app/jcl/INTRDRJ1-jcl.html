Summary

This JCL job performs two sequential operations: first, it creates a backup copy of a card demo FTP test dataset, and then it submits another JCL member for execution by copying it to the internal reader, enabling automated job submission. ### Key Functionalities: - Creates a backup of the card demo FTP test dataset (AWS.M2.CARDEMO.FTP.TEST) by reproducing its contents into a backup dataset (AWS.M2.CARDEMO.FTP.TEST.BKUP) using the IDCAMS REPRO utility. - Reads the JCL member INTRDRJ2 from the card demo JCL library (AWS.M2.CARDDEMO.JCL) and submits it for execution by writing it to the internal reader, enabling automated chained job submission.

Step 1 - IDCAMS - CarDemo FTP Test Data Full Backup

Business Rules

Supporting Code

| Rule | Supporting JCL Code Lines | Explanation | |------|--------------------------|-------------| | **CarDemo FTP Test Data Full Backup** | `//IN DD DSN=AWS.M2.CARDEMO.FTP.TEST,DISP=SHR` `//OUT DD DSN=AWS.M2.CARDEMO.FTP.TEST.BKUP,DISP=SHR` `REPRO IFILE(IN) OFILE(OUT)` | The `REPRO` command reads from the `IN` file (source) and writes to the `OUT` file (backup), triggering the full backup action | | **Backup Destination File Pre-existence Requirement** | `//OUT DD DSN=AWS.M2.CARDEMO.FTP.TEST.BKUP,DISP=SHR` | `DISP=SHR` indicates the backup file must **already exist** on the system — the job does not create it; it only opens and writes to a pre-existing file | | **Exact Data Replication Without Transformation** | `REPRO IFILE(IN) OFILE(OUT)` | The `REPRO` command with only `IFILE` and `OFILE` parameters and **no additional filtering options** (such as `SKIP`, `COUNT`, `FROMKEY`, `TOKEY`) means all records are copied exactly as-is with zero transformation |
