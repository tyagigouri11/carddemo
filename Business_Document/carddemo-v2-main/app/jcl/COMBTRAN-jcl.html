Summary

This JCL job (COMBTRAN) combines two transaction sources — a backup transaction file and a system transaction file — into a single unified dataset by sorting them by Transaction ID, and then loads the combined result into a VSAM KSDS file used for card transaction processing. ### Key Functionalities: - Merges two transaction generation data group (GDG) files — the current backup transaction file (AWS.M2.CARDDEMO.TRANSACT.BKUP generation 0) and the current system transaction file (AWS.M2.CARDDEMO.SYSTRAN generation 0) — into one combined dataset. - Sorts the merged transactions in ascending order by Transaction ID (TRAN-ID), a 16-character alphanumeric field starting at position 1, ensuring a consistent and ordered transaction sequence. - Writes the sorted, combined transactions to a new GDG generation (+1) of AWS.M2.CARDDEMO.TRANSACT.COMBINED, creating a new cataloged sequential dataset on disk. - Reproduces (loads) the newly created combined transaction GDG file into the VSAM KSDS file (AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS), making the consolidated transactions available for downstream card transaction processing.

Dataset Information (4)

Dataset/Table Name Type Usage
AWS.M2.CARDDEMO.TRANSACT.BKUP(0) GDG Input — current generation (0) of the transaction backup file; read during the sort merge step as one of two input sources; shared disposition (existing dataset, no changes to catalog entry)
AWS.M2.CARDDEMO.SYSTRAN(0) GDG Input — current generation (0) of the system transaction file; read during the sort merge step as the second input source; shared disposition (existing dataset, no changes to catalog entry)
AWS.M2.CARDDEMO.TRANSACT.COMBINED(+1) GDG Output — new next generation (+1) created and cataloged during the sort step; receives the merged and sorted transaction records; also used as input in the subsequent IDCAMS REPRO step to load into VSAM; retained on disk if the job completes successfully, deleted if the step fails
AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS VSAM_KSDS Output — existing VSAM Key-Sequenced Dataset for card transactions; loaded with the combined and sorted transaction records via IDCAMS REPRO; shared disposition, updated in place

Business Rules

Supporting Code

Rule 1 — Merge Transaction Records from Multiple Sources: //SORTIN DD DISP=SHR, // DSN=AWS.M2.CARDDEMO.TRANSACT.BKUP(0) // DD DISP=SHR, // DSN=AWS.M2.CARDDEMO.SYSTRAN(0) Rule 2 — Transaction ID as the Unique Transaction Identifier: //SYMNAMES DD * TRAN-ID,1,16,CH Rule 3 — Sort All Transactions in Ascending Order by Transaction ID: //SYSIN DD * SORT FIELDS=(TRAN-ID,A) Rule 4 — Create New Generation of Combined Transaction //SORTOUT DD DISP=(NEW,CATLG,DELETE), // DSN=AWS.M2.CARDDEMO.TRANSACT.COMBINED(+1) Rule 5 — Discard Incomplete Combined Transaction File on Failure: //SORTOUT DD DISP=(NEW,CATLG,DELETE), // DSN=AWS.M2.CARDDEMO.TRANSACT.COMBINED(+1)
