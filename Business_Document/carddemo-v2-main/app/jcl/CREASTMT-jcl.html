Summary

The CREASTMT job creates customer account statements by extracting and reorganizing transaction data, then generating both a plain-text statement file and an HTML-formatted statement file. It sorts transactions by card number and transaction ID, loads them into a VSAM file, and runs the statement generation program (CBSTM03A) that cross-references account, customer, and card data to produce the final outputs. ### Key Functionalities: - Deletes and recreates the transaction working VSAM KSDS file (AWS.M2.CARDDEMO.TRXFL.VSAM.KSDS) with fixed 350-byte records, indexed on a 32-byte key at position 0, to ensure a clean starting state before processing. - Sorts all transactions from the master transaction VSAM file by card number (positions 263–278, ascending) and then by transaction ID (positions 1–16, ascending), and reformats each record by placing the card number first (bytes 1–16), followed by the original transaction fields (bytes 17–278), and appending the remaining 50 bytes (bytes 279–328), writing results to a sequential work file. - Loads the sorted and reformatted sequential transaction work file into the recreated VSAM KSDS file using IDCAMS REPRO, making the data available for keyed access by the statement generation program. - Cleans up any pre-existing statement output files (HTML and plain-text) before the statement generation step to ensure no stale data carries forward. - Executes the statement generation program (CBSTM03A) which reads the sorted transaction VSAM file, cross-references card numbers to accounts (CARDXREF), retrieves account details (ACCTDATA), and customer information (CUSTDATA) to produce a plain-text statement file (80-byte records) and an HTML statement file (100-byte records), both catalogued as new datasets.

Step 1 - DELDEF01 - Transaction Working Files Cleanup Before Statement Run

Business Rules

Supporting Code

**Rule 1 — Transaction Working Files Cleanup:** ``` DELETE AWS.M2.CARDDEMO.TRXFL.SEQ DELETE AWS.M2.CARDDEMO.TRXFL.VSAM.KSDS - CLUSTER ``` **Rule 2 — Missing Transaction File Tolerance:** ``` DELETE AWS.M2.CARDDEMO.TRXFL.SEQ DELETE AWS.M2.CARDDEMO.TRXFL.VSAM.KSDS - CLUSTER SET MAXCC = 0 ``` **Rule 3 — VSAM Transaction Working File Structure Definition:** ``` DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.TRXFL.VSAM.KSDS) - KEYS(32 0) - RECORDSIZE(350 350) - INDEXED) - DATA (NAME(AWS.M2.CARDDEMO.TRXFL.DATA) - CISZ(4096)) - INDEX (NAME(AWS.M2.CARDDEMO.TRXFL.INDEX)) ``` **Rule 4 — Secure Data Erasure Policy:** ``` DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.TRXFL.VSAM.KSDS) - ERASE - ...) ```

Step 2 - STEP010 - Sort Transactions by Card Number and Transaction ID

Business Rules

Supporting Code

**Rule 1 — Sort Transactions by Card Number and Transaction ID:** ```jcl //SORTIN DD DISP=SHR,DSN=AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS //SORTOUT DD DSN=AWS.M2.CARDDEMO.TRXFL.SEQ, // DISP=(NEW,CATLG,DELETE),... //SYSIN DD * SORT FIELDS=(263,16,CH,A,1,16,CH,A) ``` - `263,16,CH,A` → Primary sort key: Card Number, 16 characters starting at position 263, Ascending - `1,16,CH,A` → Secondary sort key: Transaction ID, 16 characters starting at position 1, Ascending --- **Rule 2 — Restructure Transaction Record Layout:** ```jcl //SYSIN DD * OUTREC FIELDS=(1:263,16,17:1,262,279:279,50) ``` - `1:263,16` → Output positions 1–16 ← Input positions 263–278 (Card Number promoted to front) - `17:1,262` → Output positions 17–278 ← Input positions 1–262 (Transaction ID + detail fields) - `279:279,50` → Output positions 279–328 ← Input positions 279–328 (remaining fields, unchanged)

Step 5 - STEP040 - Customer Account Statement Generation

Business Rules

Supporting Code

```jcl /* Conditional Execution — Step is skipped if any prior step failed */ //STEP040 EXEC PGM=CBSTM03A,COND=(0,NE) /* Input Files — Four data sources required for statement generation */ //TRNXFILE DD DISP=SHR,DSN=AWS.M2.CARDDEMO.TRXFL.VSAM.KSDS //XREFFILE DD DISP=SHR,DSN=AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS //ACCTFILE DD DISP=SHR,DSN=AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS //CUSTFILE DD DISP=SHR,DSN=AWS.M2.CARDDEMO.CUSTDATA.VSAM.KSDS /* Output File 1 — Print-Ready Statement: Kept on success, Deleted on failure */ //STMTFILE DD DISP=(NEW,CATLG,DELETE), // DSN=AWS.M2.CARDDEMO.STATEMNT.PS /* Output File 2 — HTML Statement: Kept on success, Deleted on failure */ //HTMLFILE DD DISP=(NEW,CATLG,DELETE), // DSN=AWS.M2.CARDDEMO.STATEMNT.HTML ``` | Code Element | Business Rule Derived | |---|---| | `COND=(0,NE)` | Statement generation is **skipped entirely** if any prior step (initialization, sort, VSAM load, or file cleanup) did not complete successfully | | `TRNXFILE`, `XREFFILE`, `ACCTFILE`, `CUSTFILE` with `DISP=SHR` | All four business data sources (transactions, card-account mapping, account financials, customer details) must be available and readable before statements can be generated | | `STMTFILE DISP=(NEW,CATLG,DELETE)` | The print statement file is a **new file each run**; it is permanently saved only if the program succeeds — automatically discarded if the program fails | | `HTMLFILE DISP=(NEW,CATLG,DELETE)` | The HTML statement file is a **new file each run**; it is permanently saved only if the program succeeds — automatically discarded if the program fails |
