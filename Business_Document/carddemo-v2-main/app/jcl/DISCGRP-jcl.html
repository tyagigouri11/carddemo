Summary

This JCL job sets up the Disclosure Group VSAM file by first removing any existing version, recreating it with defined storage and key specifications, and then loading it with data from a sequential flat file. The job ensures a fresh, properly structured Disclosure Group file is available for the CardDemo application. ### Key Functionalities: - Deletes the existing Disclosure Group VSAM KSDS cluster (AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS) to ensure a clean slate, suppressing any errors if the file does not exist. - Recreates the Disclosure Group VSAM KSDS cluster with a fixed record size of 50 bytes, a 16-byte key starting at position 0, allocated on 1 primary and 5 secondary cylinders on volume AWSHJ1, with share options (2 3) and erase-on-delete enabled. - Loads the newly created Disclosure Group VSAM file by copying all records from the sequential source file (AWS.M2.CARDDEMO.DISCGRP.PS) into the VSAM KSDS cluster.

Step 1 - STEP05 - Delete Existing Disclosure Group VSAM File

Business Rules

Supporting Code

Rule 1 — Delete Existing Disclosure Group VSAM ``` DELETE AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS - CLUSTER ``` Rule 2 — Suppress Deletion Failure for Re-Runability: ``` SET MAXCC = 0 ```

Step 2 - STEP10 - Disclosure Group Master File Creation

Business Rules

Supporting Code

**Rule 1 — Disclosure Group Master File Creation:** ```jcl DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS) - INDEXED - ) - DATA (NAME(AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS.DATA) - ) - INDEX (NAME(AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS.INDEX) - ) ``` --- **Rule 2 — Disclosure Group Record Unique Key Identification:** ```jcl KEYS(16 0) ``` *(Key length = 16 characters; Key offset = 0, meaning the key starts at the very first byte of each record)* --- **Rule 3 — Disclosure Group Fixed Record Size Enforcement:** ```jcl RECORDSIZE(50 50) ``` *(Minimum record size = 50 bytes; Maximum record size = 50 bytes → fixed-length records)* --- **Rule 4 — Disclosure Group Sensitive Data Erasure on Deletion:** ```jcl ERASE ``` *(Physical erasure of all data from storage media upon file deletion)* --- **Rule 5 — Disclosure Group Concurrent Access Control:** ```jcl SHAREOPTIONS(2 3) ``` *(Value 2 = within a single system: multiple readers allowed, only one writer at a time; Value 3 = across multiple systems: concurrent reads and writes permitted)*

Step 3 - STEP15 - Load All Disclosure Group Records from Flat File into VSAM

Business Rules

Supporting Code

/* Rule 1 - Load All Disclosure Group Records from Flat File into VSAM */ //DISCGRP DD DISP=SHR, // DSN=AWS.M2.CARDDEMO.DISCGRP.PS ← Source: All Disclosure Group records //DISCVSAM DD DISP=OLD, // DSN=AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS ← Target: Disclosure Group VSAM KSDS REPRO INFILE(DISCGRP) OUTFILE(DISCVSAM) ← Copy ALL records, no filtering /* Rule 2 - Protect Source Disclosure Group Flat File During Load */ //DISCGRP DD DISP=SHR, ← SHR = Shared/Read-Only access // DSN=AWS.M2.CARDDEMO.DISCGRP.PS ← Source file is never modified /* Rule 3 - Exclusive Access Control on Target Disclosure Group VSAM During Load */ //DISCVSAM DD DISP=OLD, ← OLD = Exclusive access, no concurrent access allowed // DSN=AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS ← Target VSAM locked during entire load operation
