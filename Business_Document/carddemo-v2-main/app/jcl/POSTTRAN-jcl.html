Summary

The POSTTRAN job executes program CBTRN02C to process daily credit card transactions by validating and posting them against account and cross-reference data. It reads daily transaction records, matches them against card and account information, posts valid transactions to the transaction and transaction category balance files, and writes rejected transactions to a new generation output file. ### Key Functionalities: - Reads daily transaction records from the daily transaction sequential file (AWS.M2.CARDDEMO.DALYTRAN.PS) as the primary input for processing - Validates each transaction by cross-referencing card numbers against the card cross-reference VSAM file (AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS) to resolve account associations - Verifies and updates account data in the account master VSAM file (AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS) for valid transactions - Posts accepted transactions to the transaction VSAM file (AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS) as a permanent transaction record - Updates transaction category balances in the transaction category balance VSAM file (AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS) to reflect new transaction activity - Writes rejected/invalid transactions to a new generation data group file (AWS.M2.CARDDEMO.DALYREJS(+1)) with fixed-length 430-byte records for downstream error handling or review

Dataset Information (6)

Dataset/Table Name Type Usage
AWS.M2.CARDDEMO.DALYTRAN.PS SEQUENTIAL Input file containing daily credit card transactions to be processed; opened with shared disposition indicating it was created by a prior job step
AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS VSAM_KSDS Input/Output master transaction file; valid transactions are posted and stored here; opened with shared disposition allowing concurrent access
AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS VSAM_KSDS Input card-to-account cross-reference file; used to validate and resolve card numbers to account numbers during transaction processing; opened with shared disposition
AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS VSAM_KSDS Input/Output account master data file; account balances and details are read and updated for each valid transaction; opened with shared disposition
AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS VSAM_KSDS Input/Output transaction category balance file; category-level balance totals are updated to reflect newly posted transactions; opened with shared disposition
AWS.M2.CARDDEMO.DALYREJS(+1) GDG Output file for rejected/invalid transactions; a new generation is created and cataloged during this run (deleted if job fails); fixed-length records of 430 bytes; allocated 1 cylinder with 1 cylinder extension on SYSDA

```jcl //STEP15 EXEC PGM=CBTRN02C <- Invokes the Daily Transaction Posting program //DALYTRAN DD DISP=SHR, <- Primary input: Daily Transaction File (all // DSN=AWS.M2.CARDDEMO.DALYTRAN.PS card transactions for the business day) //XREFFILE DD DISP=SHR, <- Validation input: Card Cross-Reference Master // DSN=AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS (validates card number, resolves account) //ACCTFILE DD DISP=SHR, <- Validation input: Account Master // DSN=AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS (validates account linked to card) //TRANFILE DD DISP=SHR, <- Output: Transaction Master // DSN=AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS (valid transactions posted here) //TCATBALF DD DISP=SHR, <- Output: Transaction Category Balance // DSN=AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS (category balances updated per valid transaction) //DALYREJS DD DISP=(NEW,CATLG,DELETE), <- Output: Daily Rejections File (new GDG generation) // DSN=AWS.M2.CARDDEMO.DALYREJS(+1) CATLG = retained on success // DCB=(RECFM=F,LRECL=430,BLKSIZE=0), DELETE = discarded on job failure // SPACE=(CYL,(1,1),RLSE) Fixed 430-byte records per rejection ```
