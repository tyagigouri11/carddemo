Summary

This JCL job (TRANREPT) generates a Transaction Report by first backing up the VSAM transaction file, then filtering and sorting transactions within a specific date range (January 1, 2022 to July 6, 2022), and finally producing a formatted report by cross-referencing card, transaction type, and transaction category data. ### Key Functionalities: - Backs up the VSAM transaction file (AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS) into a new generation of a Generation Data Group (GDG) dataset for archival purposes. - Filters transactions with a processing date between 2022-01-01 and 2022-07-06 (inclusive) from the backup, and sorts the qualifying records in ascending order by Card Number (16-digit field starting at position 263). - Stores the filtered and sorted transaction records into a new GDG generation dataset (AWS.M2.CARDDEMO.TRANSACT.DALY) for use in report generation. - Executes the report program (CBTRN03C) which reads the filtered transactions and cross-references them against the Card Cross-Reference (CARDXREF), Transaction Type (TRANTYPE), and Transaction Category (TRANCATG) VSAM files to enrich the data. - Reads date parameters from a date parameter file (AWS.M2.CARDDEMO.DATEPARM) to control the reporting period. - Produces a formatted Transaction Report (LRECL=133, fixed-block format) stored as a new GDG generation in AWS.M2.CARDDEMO.TRANREPT for business review.

Dataset Information (8)

Dataset/Table Name Type Usage
AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS VSAM_KSDS Input – Source transaction master file read in the first step (PRC001) to extract all transaction records for backup.
AWS.M2.CARDDEMO.TRANSACT.BKUP(+1) GDG Output – New generation created in PRC001 as a sequential backup of the VSAM transaction file (record length 350, fixed-block). Also used as input to the sort step (STEP05R) for filtering and sorting.
AWS.M2.CARDDEMO.TRANSACT.DALY(+1) GDG Output – New generation created in STEP05R containing filtered (date range 2022-01-01 to 2022-07-06) and sorted (ascending by card number) transaction records. Used as input to the report generation step (STEP10R).
AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS VSAM_KSDS Input – Card cross-reference file read by CBTRN03C (STEP10R) to look up account and customer information associated with each card number on the transactions.
AWS.M2.CARDDEMO.TRANTYPE.VSAM.KSDS VSAM_KSDS Input – Transaction type reference file read by CBTRN03C (STEP10R) to retrieve descriptive labels for each transaction type code.
AWS.M2.CARDDEMO.TRANCATG.VSAM.KSDS VSAM_KSDS Input – Transaction category reference file read by CBTRN03C (STEP10R) to retrieve descriptive labels for each transaction category code.
AWS.M2.CARDDEMO.DATEPARM SEQUENTIAL Input – Date parameter file read by CBTRN03C (STEP10R) to supply the reporting date range parameters controlling the report output.
AWS.M2.CARDDEMO.TRANREPT(+1) GDG Output – New generation created by CBTRN03C (STEP10R) containing the final formatted transaction report (record length 133, fixed-block). Catalogued and retained after the job completes.

Step 1 - PRC001 - Create Versioned Backup of Live Transaction Master File

Business Rules

Supporting Code

//PRC001 EXEC PGM=IDCAMS //FILEIN DD DISP=SHR, // DSN=AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS //FILEOUT DD DISP=(NEW,CATLG,DELETE), // DCB=(LRECL=350,RECFM=FB,BLKSIZE=0), // DSN=AWS.M2.CARDDEMO.TRANSACT.BKUP(+1) //SYSIN DD * REPRO INFILE(FILEIN) OUTFILE(FILEOUT)

Step 2 - STEP05R - Transaction Date Range Filtering

Business Rules

Supporting Code

Rule 1 — Transaction Date Range Filtering: ``` //SYMNAMES DD * TRAN-PROC-DT,305,10,CH PARM-START-DATE,C'2022-01-01' PARM-END-DATE,C'2022-07-06' //SYSIN DD * INCLUDE COND=(TRAN-PROC-DT,GE,PARM-START-DATE,AND, TRAN-PROC-DT,LE,PARM-END-DATE) ``` Rule 2 — Transaction Sorting by Card Number: ``` //SYMNAMES DD * TRAN-CARD-NUM,263,16,ZD //SYSIN DD * SORT FIELDS=(TRAN-CARD-NUM,A) ``` Rule 3 — Daily Transaction File Generation: ``` //SORTOUT DD DISP=(NEW,CATLG,DELETE), // UNIT=SYSDA, // DCB=(*.SORTIN), // SPACE=(CYL,(1,1),RLSE), // DSN=AWS.M2.CARDDEMO.TRANSACT.DALY(+1) ``` Rule 4 — Reporting Period Boundary Definition: ``` //SYMNAMES DD * PARM-START-DATE,C'2022-01-01' PARM-END-DATE,C'2022-07-06' INCLUDE COND=(TRAN-PROC-DT,GE,PARM-START-DATE,AND, TRAN-PROC-DT,LE,PARM-END-DATE) ```

Step 3 - STEP10R - Transaction Report Generation
