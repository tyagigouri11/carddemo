Summary

This JCL job (DUSRSECJ) initializes the User Security (USRSEC) VSAM file for the CardDemo application by creating and loading user credentials for both administrative and regular users. It first creates a flat sequential file with 10 predefined user records (5 administrators and 5 regular users), then rebuilds the VSAM KSDS cluster, and finally loads all user records into it. ### Key Functionalities: - Deletes any pre-existing temporary sequential file (AWS.M2.CARDDEMO.USRSEC.PS) to ensure a clean start before processing. - Creates a new sequential flat file containing exactly 10 user records: 5 administrator accounts (ADMIN001–ADMIN005) and 5 regular user accounts (USER0001–USER0005), each with first name, last name, and password, stored as fixed-length 80-byte records. - Deletes the existing VSAM KSDS cluster (AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS) and redefines it with an 8-byte key starting at position 0, fixed 80-byte record size, indexed organization, and allocated space of 45 primary and 15 secondary tracks. - Loads all 10 user security records from the sequential flat file into the newly created VSAM KSDS cluster, establishing the initial user security reference data for the CardDemo application.

Dataset Information (4)

Dataset/Table Name Type Usage
AWS.M2.CARDDEMO.USRSEC.PS SEQUENTIAL Intermediate work file — initially deleted if it exists (MOD,DELETE,DELETE), then created as output in STEP01 to hold 10 user security records as fixed-length 80-byte blocks, then read as input in STEP03 to load the VSAM cluster. Cataloged on successful completion and deleted on failure.
AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS VSAM_KSDS Primary output — deleted and redefined in STEP02 with an 8-byte key at offset 0, fixed 80-byte record size, 45 primary and 15 secondary tracks, then loaded with all 10 user security records in STEP03 via REPRO. Serves as the permanent user security reference store for the CardDemo application.
AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS.DAT VSAM_KSDS Data component of the VSAM KSDS cluster — automatically defined by IDCAMS in STEP02 as the data portion of AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS.
AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS.IDX VSAM_KSDS Index component of the VSAM KSDS cluster — automatically defined by IDCAMS in STEP02 as the index portion of AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS.

Step 3 - STEP02 - Existing User Security Database Removal

Business Rules

Supporting Code

**Scenario 1 — Existing User Security Database Removal:** ```jcl DELETE AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS ``` **Scenario 2 — First-Time Initialization Error Suppression:** ```jcl DELETE AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS SET MAXCC = 0 ``` **Scenario 3 — User ID as Unique Database Lookup Key:** ```jcl DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS) - KEYS(8,0) - ``` **Scenario 4 — Fixed 80-Character User Record Size Enforcement:** ```jcl DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS) - RECORDSIZE(80,80) - ``` **Scenario 5 — User Security Database Reusability:** ```jcl DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS) - REUSE - ``` **Scenario 6 — Free Space Reservation for Future User Additions:** ```jcl DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS) - FREESPACE(10,15) - ``` **Scenario 7 — Indexed Structure with Separate Data and Index Components:** ```jcl DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS) - INDEXED - DATA (NAME(AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS.DAT)) - INDEX (NAME(AWS.M2.CARDDEMO.USRSEC.VSAM.KSDS.IDX)) ```
