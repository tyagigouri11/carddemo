Summary

This JCL job (UNLDGSAM) executes an IMS DL/I batch program (DBUNLDGS) using the IMS region controller (DFSRRC00) to unload data from an IMS Payment Authorization database (PAUTHDB) into two GSAM (Generalized Sequential Access Method) output files — one for root segments and one for child segments — as part of the CardDemo application's data migration or extract process. ### Key Functionalities: - Executes the IMS DL/I batch unload program (DBUNLDGS) using PSB DLIGSAMP to read from the IMS Payment Authorization database (PAUTHDB) - Unloads IMS root segment records from the Payment Authorization database into a sequential GSAM output file (AWS.M2.CARDDEMO.PAUTDB.ROOT.GSAM), retaining the file after the job completes - Unloads IMS child segment records from the Payment Authorization database into a separate sequential GSAM output file (AWS.M2.CARDDEMO.PAUTDB.CHILD.GSAM), retaining the file after the job completes - Reads the IMS Payment Authorization primary database (OEM.IMS.IMSP.PAUTHDB) and its index (OEM.IMS.IMSP.PAUTHDBX) as source data for the unload operation - Utilizes IMS PSB and DBD libraries to define the program's database access structure and segment layouts during execution

Business Rules

Supporting Code

**Rule 1 — Payment Authorization Database Full Extraction with Hierarchical Record Separation:** ```jcl //STEP01 EXEC PGM=DFSRRC00, // PARM='DLI,DBUNLDGS,DLIGSAMP,,,,,,,,,,,N' //PASFILOP DD DSN=AWS.M2.CARDDEMO.PAUTDB.ROOT.GSAM, // DISP=(OLD,KEEP,KEEP) //PADFILOP DD DSN=AWS.M2.CARDDEMO.PAUTDB.CHILD.GSAM, // DISP=(OLD,KEEP,KEEP) //DDPAUTP0 DD DSN=OEM.IMS.IMSP.PAUTHDB,DISP=SHR //DDPAUTX0 DD DSN=OEM.IMS.IMSP.PAUTHDBX,DISP=SHR ``` --- **Rule 2 — Output File Pre-existence Validation:** ```jcl //PASFILOP DD DSN=AWS.M2.CARDDEMO.PAUTDB.ROOT.GSAM, // DISP=(OLD,KEEP,KEEP) //PADFILOP DD DSN=AWS.M2.CARDDEMO.PAUTDB.CHILD.GSAM, // DISP=(OLD,KEEP,KEEP) ``` > `DISP=(OLD,...)` — The first positional value `OLD` mandates that the dataset must already exist before the job runs. --- **Rule 3 — Output File Retention Policy:** ```jcl //PASFILOP DD DSN=AWS.M2.CARDDEMO.PAUTDB.ROOT.GSAM, // DISP=(OLD,KEEP,KEEP) //PADFILOP DD DSN=AWS.M2.CARDDEMO.PAUTDB.CHILD.GSAM, // DISP=(OLD,KEEP,KEEP) ``` > `DISP=(OLD,KEEP,KEEP)` — Second positional `KEEP` = retain on normal completion; Third positional `KEEP` = retain on abnormal termination. --- **Rule 4 — Concurrent Shared Access to Payment Authorization Database:** ```jcl //DDPAUTP0 DD DSN=OEM.IMS.IMSP.PAUTHDB,DISP=SHR //DDPAUTX0 DD DSN=OEM.IMS.IMSP.PAUTHDBX,DISP=SHR ``` > `DISP=SHR` — Shared disposition allows multiple jobs to access the same dataset simultaneously. --- **Rule 5 — PSB-Based Authorization for Database Access:** ```jcl //STEP01 EXEC PGM=DFSRRC00, // PARM='DLI,DBUNLDGS,DLIGSAMP,,,,,,,,,,,N' //IMS DD DISP=SHR,DSN=OEM.IMS.IMSP.PSBLIB // DD DISP=SHR,DSN=OEM.IMS.IMSP.DBDLIB ``` > `DLIGSAMP` in PARM — Third positional parameter specifies the PSB name governing database access authorization. `PSBLIB` and `DBDLIB` provide the PSB and database structure definitions.
