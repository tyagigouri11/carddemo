Summary

This JCL job (UNLDPADB) unloads data from an IMS database (Payment Authorization Database - PAUTDB) into two sequential output files: a root segment file and a child segment file. The job first cleans up any previously existing output files, then executes the IMS DL/I batch program (PAUDBUNL/PAUTBUNL) to extract and write the IMS database records into flat files for downstream processing or migration purposes. ### Key Functionalities: - Deletes any pre-existing output files (root and child) before the unload process begins, ensuring a clean slate for the new extraction run. - Unloads IMS Payment Authorization Database (PAUTDB) root segment records into a sequential output file (AWS.M2.CARDDEMO.PAUTDB.ROOT.FILEO) with a fixed-block record length of 100 bytes. - Unloads IMS Payment Authorization Database (PAUTDB) child segment records into a sequential output file (AWS.M2.CARDDEMO.PAUTDB.CHILD.FILEO) with a fixed-block record length of 206 bytes. - Accesses the IMS Payment Authorization Database (PAUTHDB) and its index (PAUTHDBX) as source data for the unload operation. - Uses IMS DL/I batch execution environment (DFSRRC00) with Program Specification Block (PSB) and Database Definition (DBD) libraries to navigate and read the IMS database hierarchy.

Step 1 - STEP0 - Delete Existing Root Payment Authorization Output File Before Fresh Extraction

Business Rules

Supporting Code

/* Rule 1 - Unconditional deletion of Root Payment Authorization Output File */ //DD1 DD DSN=AWS.M2.CARDDEMO.PAUTDB.ROOT.FILEO, // DISP=(OLD,DELETE,DELETE) /* DISP=(OLD, → File must already exist (from a prior run) DELETE, → DELETE on normal/successful completion of STEP0 DELETE) → DELETE on abnormal/failure completion of STEP0 Both outcomes result in deletion — deletion is unconditional */ /* Rule 2 - Unconditional deletion of Child Payment Authorization Output File */ //DD2 DD DSN=AWS.M2.CARDDEMO.PAUTDB.CHILD.FILEO, // DISP=(OLD,DELETE,DELETE) /* DISP=(OLD, → File must already exist (from a prior run) DELETE, → DELETE on normal/successful completion of STEP0 DELETE) → DELETE on abnormal/failure completion of STEP0 Both outcomes result in deletion — deletion is unconditional */ /* Rule 3 - Both files deleted together as a paired set */ //DD1 DD DSN=AWS.M2.CARDDEMO.PAUTDB.ROOT.FILEO, // DISP=(OLD,DELETE,DELETE) //DD2 DD DSN=AWS.M2.CARDDEMO.PAUTDB.CHILD.FILEO, // DISP=(OLD,DELETE,DELETE) /* Both DD1 and DD2 carry identical DISP=(OLD,DELETE,DELETE) dispositions within the same step (STEP0), enforcing that both files are always cleared together — no selective retention of either file is possible */

Step 2 - STEP01 - Payment Authorization Database Unload

Business Rules

Supporting Code

**Program Invocation — Payment Authorization Database Unload via IMS Batch DL/I:** ```jcl //STEP01 EXEC PGM=DFSRRC00, // PARM='DLI,PAUDBUNL,PAUTBUNL,,,,,,,,,,,N' ``` **Input — IMS Payment Authorization Primary Database (Shared Read):** ```jcl //DDPAUTP0 DD DSN=OEM.IMS.IMSP.PAUTHDB,DISP=SHR ``` **Input — IMS Payment Authorization Index Database (Shared Read):** ```jcl //DDPAUTX0 DD DSN=OEM.IMS.IMSP.PAUTHDBX,DISP=SHR ``` **Output — Root-Level Payment Authorization Records (100 bytes, Retain on Success / Delete on Failure):** ```jcl //OUTFIL1 DD DSN=AWS.M2.CARDDEMO.PAUTDB.ROOT.FILEO, // DISP=(NEW,CATLG,DELETE), // DCB=(LRECL=100,BLKSIZE=0,RECFM=FB), // UNIT=3390,SPACE=(400,(20,20),RLSE) ``` **Output — Child-Level Payment Authorization Records (206 bytes, Retain on Success / Delete on Failure):** ```jcl //OUTFIL2 DD DSN=AWS.M2.CARDDEMO.PAUTDB.CHILD.FILEO, // DISP=(NEW,CATLG,DELETE), // DCB=(LRECL=206,BLKSIZE=0,RECFM=FB), // UNIT=3390,SPACE=(400,(20,20),RLSE) ```
