Summary

This JCL job (CREADB2) sets up the DB2 database environment for the CardDemo application by freeing existing DB2 plans and packages, creating new DB2 database objects (tables/structures), and loading transaction type and card category data into the DB2 system DAZ1. ### Key Functionalities: - Frees existing DB2 plans (CARDDEMO, COTRTLIC) and all packages under COTRTLIC to allow a clean re-creation of the database environment. - Executes DB2 DDL statements from the DB2CREAT control member to create the required CardDemo database tables and objects in DB2 system DAZ1. - Loads transaction type reference data into DB2 by running SQL statements defined in the DB2LTTYP control member. - Loads card category reference data into DB2 by running SQL statements defined in the DB2LTCAT control member. - Steps RUNTEP2 and LDTCCAT are conditionally executed only if all prior steps complete successfully (COND=(0,NE) skips execution on any non-zero return code).

Step 4 - RUNTEP2 - Load Type Reference Data into Card Demo Database

Business Rules

Supporting Code

**Rule 1 — Load Type Reference Data into Card Demo Database:** ```jcl //SYSTSIN DD * DSN SYSTEM(DAZ1) RUN PROGRAM(DSNTEP4) - PLAN(DSNTEP4) - PARMS('/ALIGN(LHS) MIXED') /* //SYSIN DD DISP=SHR,DSN=&LBNM..CNTL(DB2LTTYP) ``` > `DSN SYSTEM(DAZ1)` — targets DB2 subsystem DAZ1; `RUN PROGRAM(DSNTEP4)` — invokes DB2 SQL processor; `SYSIN=AWS.M2.CARDDEMO.CNTL(DB2LTTYP)` — source SQL script for type reference data --- **Rule 2 — Mixed Case Data Value Preservation:** ```jcl PARMS('/ALIGN(LHS) MIXED') ``` > `MIXED` parameter instructs DSNTEP4 to process SQL statements and data values in mixed case (both uppercase and lowercase), preserving original casing of all type reference data values --- **Rule 3 — Shared Read-Only Access to Source Script:** ```jcl //SYSIN DD DISP=SHR,DSN=&LBNM..CNTL(DB2LTTYP) ``` > `DISP=SHR` — shared disposition ensures the DB2LTTYP script is accessed as read-only and is available for concurrent access; `&LBNM` resolves to `AWS.M2.CARDDEMO` --- **Rule 4 — Unconditional Execution:** ```jcl //RUNTEP2 EXEC PGM=IKJEFT01,DYNAMNBR=20 ``` > No `COND=` parameter is present on the EXEC statement — this confirms the step executes unconditionally regardless of any prior step return codes

Step 5 - LDTCCAT - Conditional Execution Gate for Category Reference Data Loading

Business Rules

Supporting Code

**Rule 1 — Conditional Execution Gate (Decision Rule):** ```jcl //LDTCCAT EXEC PGM=IKJEFT01,DYNAMNBR=20,COND=(0,NE) ``` > `COND=(0,NE)` — Bypass this step if the value 0 is NOT EQUAL to any prior step's return code. > Translated: Run LDTCCAT **only** when ALL prior steps returned RC = 0. > Skip LDTCCAT if **any** prior step returned RC ≠ 0. --- **Rule 2 — Category Reference Data Loading (Action Rule):** ```jcl //SYSTSIN DD * DSN SYSTEM(DAZ1) RUN PROGRAM(DSNTEP4) - PLAN(DSNTEP4) - PARMS('/ALIGN(LHS) MIXED') /* //SYSIN DD DISP=SHR,DSN=&LBNM..CNTL(DB2LTCAT) ``` > - `DSN SYSTEM(DAZ1)` — Targets DB2 subsystem **DAZ1** for all SQL execution. > - `RUN PROGRAM(DSNTEP4)` — Executes the DB2 interactive SQL runner against the DB2LTCAT script. > - `PARMS('/ALIGN(LHS) MIXED')` — `MIXED` parameter ensures mixed-case (upper and lowercase) data values in category reference data are fully supported and preserved. > - `DSN=&LBNM..CNTL(DB2LTCAT)` — Resolves to `AWS.M2.CARDDEMO.CNTL(DB2LTCAT)`, the shared read-only SQL source script containing all category and classification reference data INSERT/UPDATE statements.
