Summary

This JCL job (TRANEXTR) extracts Transaction Type and Transaction Category reference data from DB2 tables in the CARDDEMO application, backs up the existing flat files, replaces them with freshly extracted data, and ensures the backup generation data sets are cataloged for recovery purposes. ### Key Functionalities: - Backs up the existing Transaction Type flat file (TRANTYPE.PS) to a new generation in a Generation Data Group (GDG), creating a versioned copy with fixed-length 60-byte records. - Backs up the existing Transaction Category flat file (TRANCATG.PS) to a new generation in a Generation Data Group (GDG), creating a versioned copy with fixed-length 60-byte records. - Deletes the current Transaction Type (TRANTYPE.PS) and Transaction Category (TRANCATG.PS) flat files to prepare for fresh extraction. - Extracts Transaction Type data from the DB2 table CARDDEMO.TRANSACTION_TYPE by concatenating TR_TYPE, TR_DESCRIPTION (50 characters), and 8 trailing zeros into a 60-character fixed-length record, ordered by TR_TYPE, and writes the output to a new TRANTYPE.PS sequential file. - Extracts Transaction Category data from the DB2 table CARDDEMO.TRANSACTION_TYPE_CATEGORY by concatenating TRC_TYPE_CODE, TRC_TYPE_CATEGORY, TRC_CAT_DATA (50 characters), and 4 trailing zeros into a 60-character fixed-length record, ordered by TRC_TYPE_CODE and TRC_TYPE_CATEGORY, and writes the output to a new TRANCATG.PS sequential file.

Step 1 - STEP10 - Unconditional Backup of Transaction Type Reference File

Business Rules

Supporting Code

/* Rule 1 - Unconditional Execution and New Backup Generation Creation */ //STEP10 EXEC PGM=IEBGENER /* No COND= means unconditional execution */ //SYSUT1 DD DISP=SHR,DSN=&HLQ..TRANTYPE.PS /* Source: Current Transaction Type reference file */ //SYSUT2 DD DSN=&HLQ..TRANTYPE.BKUP(+1), /* Destination: New backup generation (+1) */ // DISP=(NEW,CATLG), /* New file, permanently cataloged on success */ // SPACE=(TRK,(1,1),RLSE) /* Unused space released after write */ /* Rule 2 - Backup File Format Definition */ //SYSUT2 DD DSN=&HLQ..TRANTYPE.BKUP(+1), /* Backup generation destination */ // DCB=(LRECL=60,RECFM=FB,BLKSIZE=600) /* Fixed 60-char records, uniform length enforced */ /* Rule 3 - No Transformation, Straight Copy */ //SYSIN DD DUMMY /* No copy instructions = complete unmodified copy */ //SYSUT1 DD DISP=SHR,DSN=&HLQ..TRANTYPE.PS /* Source read in shared mode */ //SYSUT2 DD DSN=&HLQ..TRANTYPE.BKUP(+1) /* All records copied as-is to backup */

Step 2 - STEP20 - Conditional Execution of Transaction Category File Backup

Business Rules

Supporting Code

/* Rule 1 — Conditional Execution: Transaction Category backup depends on prior step success */ //STEP20 EXEC PGM=IEBGENER,COND=(0,NE) /* COND=(0,NE): Bypass STEP20 if 0 is NOT EQUAL to any prior return code. Meaning: STEP20 runs ONLY when ALL prior steps returned RC=0 exactly. Any non-zero RC from STEP10 causes STEP20 to be skipped. */ /* Rule 2 — Backup Creation: Full unmodified copy to new historical generation */ //SYSUT1 DD DISP=SHR,DSN=&HLQ..TRANCATG.PS /* Source: Current Transaction Category reference file, opened in shared read-only mode */ //SYSUT2 DD DSN=&HLQ..TRANCATG.PS.BKUP(+1), // DISP=(NEW,CATLG), /* Destination: New generation (+1) — permanently cataloged on success */ //SYSIN DD DUMMY /* DUMMY: No copy instructions — performs a complete straight copy with no transformation */ /* Rule 3 — File Format Standards: Fixed 60-character records, space released */ // DCB=(LRECL=60,RECFM=FB,BLKSIZE=600), /* LRECL=60: Each record is exactly 60 characters RECFM=FB: Fixed Block — every record is the same length */ // SPACE=(TRK,(1,1),RLSE) /* RLSE: Unused allocated space is automatically released after writing */

Step 3 - STEP30 - Conditional Execution of Working File Cleanup Based on Backup Success

Business Rules

Supporting Code

**Scenario 1 — Conditional Execution Based on Backup Success:** ```jcl //STEP30 EXEC PGM=IEFBR14,COND=(0,NE) ``` > `COND=(0,NE)` — Skip STEP30 if 0 is NOT EQUAL to any prior step's return code. Executes only when ALL prior steps (STEP10 and STEP20) returned RC=0. --- **Scenario 2 — Deletion of Transaction Type Working ** ```jcl //DD01 DD DISP=(MOD,DELETE,DELETE), // UNIT=SYSDA, // SPACE=(TRK,(1,1)), // DSN=&HLQ..TRANTYPE.PS ``` > `DISP=(MOD,DELETE,DELETE)` — The first `DELETE` removes the file on normal completion; the second `DELETE` removes it on abnormal completion. Deletion is unconditional. --- **Scenario 3 — Deletion of Transaction Category Working ** ```jcl //DD02 DD DISP=(MOD,DELETE,DELETE), // UNIT=SYSDA, // SPACE=(TRK,(1,1)), // DSN=&HLQ..TRANCATG.PS ``` > `DISP=(MOD,DELETE,DELETE)` — Same unconditional deletion logic applied to the Transaction Category working file. --- **Scenario 4 — Fault-Tolerant Deletion (File May Not Exist):** ```jcl //DD01 DD DISP=(MOD,DELETE,DELETE), // UNIT=SYSDA, // SPACE=(TRK,(1,1)), // DSN=&HLQ..TRANTYPE.PS //DD02 DD DISP=(MOD,DELETE,DELETE), // UNIT=SYSDA, // SPACE=(TRK,(1,1)), // DSN=&HLQ..TRANCATG.PS ``` > `DISP=MOD` — If the file does not exist, the system creates it first and then immediately deletes it, ensuring the step never fails due to a missing file.

Step 4 - STEP40 - Conditional Execution of Transaction Type DB2 Extract

Business Rules

Supporting Code

**Rule 1 — Conditional Execution of Transaction Type DB2 Extract:** ```jcl //STEP40 EXEC PGM=IKJEFT01,COND=(0,NE) ``` > `COND=(0,NE)` — Bypass STEP40 if 0 is NOT EQUAL to any prior step's return code; i.e., run only when all prior steps returned exactly RC=0. --- **Rule 2 — Full Transaction Type Data Retrieval from DB2:** ```jcl //SYSIN DD * FROM CARDDEMO.TRANSACTION_TYPE /* //SYSTSIN DD * DSN SYSTEM(DAZ1) RUN PROGRAM(DSNTIAUL) - PLAN(DSNTIAUL) - PARMS('SQL') /* ``` > Connects to DB2 system DAZ1 and runs DSNTIAUL in SQL mode to execute the SELECT against CARDDEMO.TRANSACTION_TYPE — no WHERE clause means all records are retrieved. --- **Rule 3 — Transaction Type Output Record Construction:** ```sql SELECT CAST(CONCAT(CONCAT( TR_TYPE ,CAST(TR_DESCRIPTION AS CHAR(50)) ) ,REPEAT('0',8) ) AS CHAR(60)) FROM CARDDEMO.TRANSACTION_TYPE ``` > Concatenation sequence: TR_TYPE → TR_DESCRIPTION padded to 50 chars → 8 zeros filler → total cast to 60 characters. --- **Rule 4 — Transaction Type Records Sorting:** ```sql ORDER BY TR_TYPE; ``` > All output records are sorted in ascending order by Transaction Type Code (TR_TYPE). --- **Rule 5 — Transaction Type Output File Lifecycle Management:** ```jcl //SYSREC00 DD DISP=(NEW,CATLG,DELETE), // DSN=&HLQ..TRANTYPE.PS, // SPACE=(TRK,(1,1),RLSE) ``` > `DISP=(NEW,CATLG,DELETE)` — New file; permanently cataloged on success (`CATLG`); automatically deleted on failure (`DELETE`).

Step 5 - STEP50 - Conditional Execution of Transaction Category Data Extract

Business Rules

Supporting Code

/* Rule 1 — Conditional Execution: COND=(4,LT) */ //STEP50 EXEC PGM=IKJEFT01,COND=(4,LT) /* Meaning: Skip STEP50 if any prior step RC > 4; Execute only if all prior steps RC <= 4 */ /* Rule 2 — Source Table for Full Data Extraction */ //SYSIN DD * SELECT CAST(...) FROM CARDDEMO.TRANSACTION_TYPE_CATEGORY /* No WHERE clause — all records are extracted without filtering */ /* Rule 3 — Record Composition and 60-Character Fixed Format */ SELECT CAST( TRC_TYPE_CODE || TRC_TYPE_CATEGORY || CAST(TRC_CAT_DATA AS CHAR(50)) || REPEAT('0',4) AS CHAR(60)) FROM CARDDEMO.TRANSACTION_TYPE_CATEGORY /* Sequence: Type Code + Category Code + Category Data (50 chars padded) + '0000' filler = 60 chars total */ /* Rule 4 — Mandatory Two-Level Sort Order */ ORDER BY TRC_TYPE_CODE , TRC_TYPE_CATEGORY; /* Primary: TRC_TYPE_CODE ascending; Secondary: TRC_TYPE_CATEGORY ascending within each type group */ /* Rule 5 — Output File Persistence Policy: Save on Success, Delete on Failure */ //SYSREC00 DD DISP=(NEW,CATLG,DELETE), // DSN=&HLQ..TRANCATG.PS, // SPACE=(TRK,(1,1),RLSE) /* NEW=create new file; CATLG=permanently save if step succeeds; DELETE=auto-delete if step fails */
